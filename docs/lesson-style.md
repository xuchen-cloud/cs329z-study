# 课程小节编排规范

本规范用于 CS329Z 互动学习版。目标是让读者知道眼前要学什么，能看懂一个例子，并能回到原文核对。

## 每个知识点怎样展开

- 沿用课程讲次、小节标题、锚点和原作者署名。在已有引导问题之下，优先用一段具体情境说明问题，再解释机制或判断依据。能通过改写原段落解决的重复，不再另加一张卡。
- 每讲优先改一到三个难点。讲流程可用有输入、动作、观察和结果的短轨迹；讲差异可用同一案例的并排比较；讲数量关系可用带假设的算例；讲诊断可并列现象、证据和检查方法。选能解释材料的形式。
- 一个示例尽量只改变一个条件。标明哪些数字是教学假设，哪些来自课件或论文。保留必要的公式、适用边界、引文和原有动手任务。
- 自测只放在真正讲知识点的小节末尾，沿用现有题库。开篇、学习目标、情境练习、阅读清单、占位说明和动手练习均不追加自测。

## 怎样判断读者学会了

- 按要检验的能力定题量。单一概念可以用两题分别测辨认和迁移；涉及多种机制、计算、故障定位或工程取舍时，用三到五题分别取证。同一小节的题目应当检验不同能力。
- 题干给出解决问题所需的信息，例如一段工具回执、两份冲突的规则、预算或日志。明确交付要求，例如选出最早出现错误的一步并指出证据，或算出结果并说明独立性假设。不要要求读者猜测题目省略的业务规则。
- 单选题给出至少三个符合情境的选项。每个干扰项对应一种具体误解；解释说明哪个事实决定了答案，以及另一个看似合理的做法为什么会失效。
- 每组题先检查整节的核心概念、方法和适用边界各由哪道题覆盖。需要比较的概念放进同一案例；关键机制可用算例或故障轨迹检验。课程安排、论文名和重复术语不需要逐项出题。
- 简答参考解写成两到三个各有作用的短段，按题目采用「从哪里看出」「怎样判断」「什么情况下会改变结论」等小标题。计算题列出条件、代入与解释；设计题写出可行做法、选择理由和验证方法。题库中用空行分段，答案直接呈现完整推理。
- 首选短句、明确单位和清晰的对照。参考答案在提交或主动对照后展示，原文、情境例子和既有动手练习用于学习，避免在自测中逐字复述它们。

## 原图和交互怎样使用

- 图需要回答明确的问题，例如读哪支箭头、比较哪两组数据。优先使用官方原课件，核实 PDF 的实际页码和原作者，保留关键坐标轴、单位、图例及相关来源。课件没有可核实的图时，使用可复核的中文例子、表格或自行绘制并注明为本版整理的示意图。
- 节选的 PNG 放在 `docs/figures/lectureNN-name.png`。在 Markdown 单独一行写图片和有意义的替代文字，紧接一行「图注：」，写一句读法并链接原课件的具体页码。构建时图片会嵌入网页与单文件版。
- 读者可直接点图片放大，关闭后回到原阅读位置。小节菜单与折叠标题沿用原标题，图源页码写在图注里。交互最好能改变一个条件并立刻看到结果。用原生控件，让键盘也能完成操作，并为离线阅读保留静态解释。
- 小屏表格宜两三列，长原文和补充细节沿用现有折叠层级。颜色用来区分类别，文字要能独立传达相同意思。

## 比较卡与关键提示

- **比较卡**用于两到四个容易串混、能够在同一维度比较的概念。标题提出具体问题，每张卡写一个术语和一到两句可观察的差别。优先把原来相应的列表改写成卡，保留首次出现的原文术语、必要引文与公式。流程顺序、数值或多个维度的对照仍可用轨迹或表格。
- **短提示**放在误解刚可能发生的位置。用「容易混淆」点出错误推断与决定性证据，用「读图提示」或「判断依据」引导观察。每条只承担一个任务。卡片与提示不改变章节层级，也不额外出题。
- 每讲挑真正合适的段落。一个知识小节内避免连续堆叠多组卡，前后正文应能把读者带到下一步。读者能直接点截图，图片旁保留读法、原 PDF 实际页码和原作者来源。
- 卡片使用标准 Markdown 引用块，各行都有 `>`。首行用 `> [!NOTE]`，次行写 `> **有哪些不同？**`，随后每行写 `> - **词条**：解释`。提示使用 `> [!TIP]` 或 `> [!IMPORTANT]`，下一行写 `> **判断依据**：一句说明。`。块前后留空行。它们在仓库中的 Markdown 也可以阅读。

## 分组交付与验收

每组只修改分配的讲义与对应图源；共享渲染器、样式与构建产物由主编统一处理。交付时注明每讲改了哪个难点、放在哪个小节、图源与页码或算例假设。主编核对事实与术语，重新构建并检查分讲页、手机宽度及离线全书。待站点所有者明确说「发布」后，再统一推送。
